# Langues de MintMail

## État (version 1.12.0)

| Langue | Interface (≈ 1 050 textes) | Aide intégrée (F1) | Ligne de commande | Statut |
|---|---|---|---|---|
| Français | ✔ (langue source) | ✔ | ✔ | référence |
| English | ✔ | ✔ | ✔ | traduit, contrôlé automatiquement ; relecture par un anglophone bienvenue |
| Nederlands | ✔ | aide en anglais | anglais | traduction **par IA, non relue** par un néerlandophone |
| Deutsch | ✔ | aide en anglais | anglais | traduction **par IA, non relue** par un germanophone |
| Español | ✔ | aide en anglais | anglais | traduction **par IA, non relue** par un hispanophone |

Les trois dernières langues ont été traduites par Claude (IA), puis contrôlées **mécaniquement** (mêmes marqueurs `%s` / `%d`, mêmes balises, mêmes espaces, aucun reste de français, couverture exacte du code,
interface simulée qui démarre dans chaque langue) — mais **pas par un locuteur natif** : le ton, les tournures et certains termes techniques peuvent être imparfaits (fichier `<langue>.status.json`).
Signalez les défauts (ou corrigez directement `mintmail/locale/<langue>.json`, puis `make test`).

Choix : **Paramètres → Apparence → Langue de l'interface** (« Automatique » suit la langue du système ; une langue sans traduction retombe sur l'anglais). Variable `MINTMAIL_LANG=nl mintmail` pour essayer
sans toucher aux réglages. Un changement de langue demande de relancer MintMail.

## Ce qui n'est PAS traduit

- Les messages d'exemple du mode démonstration (restent en français).
- Le rapport `--diagnose` et le journal d'erreurs (destinés au support, en français).
- L'analyse des échéances de tâches : seules les expressions **françaises** (« demain », « avant vendredi », « dans 3 jours »…) et les dates
  numériques (15/11, 15/11/2026) sont comprises ; « tomorrow », « next Friday » ne le sont pas encore.
- Les noms de dossiers que MintMail reconnaît chez votre fournisseur (multilingues par construction) ; les modèles de réponse livrés par défaut
  (ce sont vos données : vous les modifiez) ; les invites envoyées à l'IA (le modèle répond dans la langue réglée dans Paramètres → IA).
- Les boîtes de dialogue standard du système (choix de fichier, etc.) : elles suivent la langue de votre session.
- La grammaire des pluriels reste simple (« 3 message(s) », « 2 pair(s) ») : correcte en anglais et en espagnol, rendue par « bericht(en) » / « Nachricht(en) » en néerlandais et en allemand.
- Néerlandais, allemand, espagnol : l'aide intégrée (F1) et l'aide de la ligne de commande restent en anglais ; dates des créneaux proposés : « jueves 12 de noviembre », « Donnerstag 12 November », « donderdag 12 november ».

## Comment ça marche

- Le code source est en français : chaque texte visible passe par `tr("texte français")` (`mintmail/i18n.py`). Sans catalogue, c'est le texte français :
  le français ne peut donc pas régresser.
- Les catalogues sont dans `mintmail/locale/<langue>.json` (`{"texte français": "traduction"}`) et `help_<langue>.json` pour l'aide.
- `tools/i18n_wrap.py --check` doit toujours répondre « À ENVELOPPER : 0 » (sinon un nouveau texte français n'est pas traduisible ; `--apply` l'enveloppe) ;
  le test `tests/test_i18n.py` l'impose, ainsi que : catalogue = code (ni oubli ni reste), marqueurs `%s` / `%d` / balises identiques,
  aucun reste de français dans l'anglais, interface simulée qui démarre avec toutes les chaînes modifiées.

## Ajouter une langue

1. Pré-traduction automatique avec **votre** service d'IA compatible OpenAI (Ollama local, serveur interne, cloud) :
   ```
   MINTMAIL_TRANSLATE_KEY=... tools/translate_catalog.py --lang de --base-url http://localhost:11434/v1 --model llama3.1 --help-too
   ```
   Chaque traduction est validée (marqueurs, balises, espaces) ; les refus sont redemandés puis laissés en français. Le travail est repris là où il s'est arrêté.
2. `tools/translate_catalog.py --lang de --check` donne l'avancement ; `de.status.json` rappelle que c'est une **traduction automatique non relue**.
3. Faire relire par un locuteur, puis `make test`. Ajouter le nom de la langue dans `NAMES` (`mintmail/i18n.py`) si elle n'y est pas.
4. Les textes envoyés à l'IA du traducteur (l'interface de MintMail) ne contiennent aucune donnée personnelle ; la clé n'est jamais affichée ni enregistrée.

## Faire relire une traduction par un locuteur

Les traductions néerlandaise, allemande et espagnole sont de l'IA, contrôlées mécaniquement mais **pas relues par une personne**. La relecture se fait dans un tableur, sans toucher au code :

```
tools/review_translations.py export nl relecture-nl.csv     # tableau : français, anglais, traduction actuelle, colonne « correction » vide
# la personne ouvre le fichier (LibreOffice / Excel), écrit une correction uniquement là où c'est nécessaire, enregistre en CSV (UTF-8, séparateur « ; »)
tools/review_translations.py import nl relecture-nl.csv --reviewer "Prénom Nom"
python3 tests/run_all.py                                    # les tests vérifient les marqueurs (%s, %d, balises) comme toujours
```

- L'import est **tout ou rien** : une seule erreur (marqueur de format perdu, texte source inconnu) et rien n'est écrit ; les lignes fautives sont listées.
- Seules les cellules « correction » non vides remplacent une traduction ; les autres langues ne sont pas touchées.
- Quand **tout** a été relu, ajoutez `--complete` : `nl.status.json` indique alors `reviewed_by_human: true` avec le nom et la date. Sans cela, la langue reste déclarée « non relue » (le test l'exige).

## Maintenance

Nouveau texte dans le code → `tools/i18n_wrap.py --apply` → ajouter sa traduction dans `locale/en.json` (le test indique lesquelles manquent) →
relancer `tools/translate_catalog.py` pour les autres langues (seules les entrées manquantes sont traduites).
