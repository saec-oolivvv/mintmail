# MintMail languages

## Status

| Language | Interface (≈ 1,100 texts) | Built-in help (F1) | Command line | Status |
|---|---|---|---|---|
| Français | ✔ (source language) | ✔ | ✔ | reference |
| English | ✔ | ✔ | ✔ | translated, automatically checked; review by a native speaker welcome |
| Nederlands | ✔ | help in English | English | **AI translation, not reviewed** by a Dutch speaker |
| Deutsch | ✔ | help in English | English | **AI translation, not reviewed** by a German speaker |
| Español | ✔ | help in English | English | **AI translation, not reviewed** by a Spanish speaker |

The last three languages were translated by Claude (AI), then checked **mechanically** (same `%s` / `%d` markers, same tags, same spaces, no French left over, exact coverage of the code, a simulated interface that starts in each language) — but **not by a native speaker**: tone, phrasing and some technical terms may be imperfect (file `<language>.status.json`). Please report defects (or fix `mintmail/locale/<language>.json` directly, then `make test`).

Choice: **Settings → Appearance → Interface language** (“Automatic” follows the system language; a language without translation falls back to English). The `MINTMAIL_LANG=nl mintmail` variable tries a language without touching the settings. A language change requires restarting MintMail.

## What is NOT translated

- The sample messages of demo mode (they stay in French).
- The `--diagnose` report and the error log (meant for support, in French).
- Task due-date parsing: only **French** expressions (“demain”, “avant vendredi”, “dans 3 jours”…) and numeric dates (15/11, 15/11/2026) are understood; “tomorrow”, “next Friday” are not yet.
- Folder names MintMail recognizes at your provider (multilingual by construction); the default reply templates (they are your data: you edit them); the prompts sent to the AI (the model answers in the language set in Settings → AI).
- The system's standard dialogs (file chooser, etc.): they follow your session language.
- Plural grammar stays simple (“3 message(s)”, “2 peer(s)”): correct in English and Spanish, rendered as “bericht(en)” / “Nachricht(en)” in Dutch and German.
- Dutch, German, Spanish: the built-in help (F1) and the command-line help stay in English; proposed time-slot dates: “jueves 12 de noviembre”, “Donnerstag 12 November”, “donderdag 12 november”.

## How it works

- The source code is in French: every visible text goes through `tr("French text")` (`mintmail/i18n.py`). Without a catalog, the French text is used, so French cannot regress.
- Catalogs are in `mintmail/locale/<language>.json` (`{"French text": "translation"}`) and `help_<language>.json` for the help.
- `tools/i18n_wrap.py --check` must always answer “À ENVELOPPER : 0” (otherwise a new French text is not translatable; `--apply` wraps it); `tests/test_i18n.py` enforces it, as well as: catalog = code (nothing missing, nothing left over), identical `%s` / `%d` markers / tags, no French left in English, a simulated interface that starts with all strings changed.

## Adding a language

1. Automatic pre-translation with **your own** OpenAI-compatible AI service (local Ollama, internal server, cloud):
   ```
   MINTMAIL_TRANSLATE_KEY=... tools/translate_catalog.py --lang de --base-url http://localhost:11434/v1 --model llama3.1 --help-too
   ```
   Each translation is validated (markers, tags, spaces); refusals are asked again and then left in French. Work resumes where it stopped.
2. `tools/translate_catalog.py --lang de --check` shows progress; `de.status.json` records that it is an **unreviewed machine translation**.
3. Have a speaker review it, then `make test`. Add the language name to `NAMES` (`mintmail/i18n.py`) if it is not there.
4. The texts sent to the translator's AI (MintMail's interface) contain no personal data; the key is never displayed or stored.

## Having a speaker review a translation

The Dutch, German and Spanish translations are AI-made, mechanically checked but **not reviewed by a person**. Review is done in a spreadsheet, without touching the code:

```
tools/review_translations.py export nl review-nl.csv     # table: French, English, current translation, empty “correction” column
# the person opens the file (LibreOffice / Excel), writes a correction only where needed, saves as CSV (UTF-8, “;” separator)
tools/review_translations.py import nl review-nl.csv --reviewer "First Last"
python3 tests/run_all.py                                 # the tests check the markers (%s, %d, tags) as always
```

- Import is **all or nothing**: a single error (lost format marker, unknown source text) and nothing is written; the faulty lines are listed.
- Only non-empty “correction” cells replace a translation; the other languages are not touched.
- When **everything** has been reviewed, add `--complete`: `nl.status.json` then says `reviewed_by_human: true` with the name and date. Without it the language stays declared “unreviewed” (the test requires it).

## Maintenance

New text in the code → `tools/i18n_wrap.py --apply` → add its translation to `locale/en.json` (the test says which are missing) → rerun `tools/translate_catalog.py` for the other languages (only missing entries are translated).
